# План проверки и автоматизации мобильного приложения

## 1. Объект тестирования

Мобильное приложение **«Мобильный хоспис»**.

---

## 2. Цель тестирования

Проверить корректность работы основных функций мобильного приложения, навигации между экранами, обработки пользовательских данных и отображения элементов пользовательского интерфейса.

---

## 3. Область тестирования

В рамках дипломного проекта проверяются следующие функции приложения:

- авторизация пользователя;
- обработка корректных и некорректных учетных данных;
- переход между разделами приложения;
- работа бокового меню;
- просмотр списка новостей;
- раскрытие содержимого новости;
- создание новости;
- удаление новости;
- переход в раздел «Наша миссия»;
- выход из учетной записи.

В рамках проекта **не проверяются**:

- серверная часть приложения;
- безопасность хранения данных;
- производительность приложения;
- работа приложения при нестабильном интернет-соединении;
- отображение интерфейса на различных устройствах и версиях Android.

---

## 4. Виды тестирования

В ходе выполнения дипломного проекта используются:

- функциональное тестирование;
- UI-тестирование;
- позитивное тестирование;
- негативное тестирование;
- регрессионное тестирование;
- исследовательское тестирование.

---

## 5. Тестовое окружение

- операционная система: Windows 11;
- Android Studio;
- Android Emulator (Pixel 4);
- Android API 32;
- Gradle 7.2;
- язык программирования Kotlin.

## 8. Автоматизированные проверки

В рамках дипломного проекта автоматизированы следующие сценарии:

- успешная авторизация;
- авторизация с неверным логином;
- авторизация с неверным паролем;
- авторизация с пустыми полями;
- открытие списка новостей;
- раскрытие первой новости;
- создание новости;
- удаление новости;
- открытие раздела «Наша миссия»;
- проверка работы бокового меню;
- выход из учетной записи.

---

## 9. Проверки, выполняемые вручную

Вручную выполняются проверки:

- редактирования новости;
- фильтрации новостей;
- визуального соответствия пользовательского интерфейса макету;
- отображения длинных текстов;
- удобства использования приложения;
- исследовательское тестирование.

---

## 10. Возможные риски

Во время автоматизации могут возникнуть следующие риски:

- нестабильная работа Android Emulator;
- изменение структуры пользовательского интерфейса;
- изменение тестовых данных;
- нестабильная работа сети;
- изменение идентификаторов элементов интерфейса;
- зависимость тестов от состояния данных приложения.
