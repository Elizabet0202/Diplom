# План проверки и автоматизации мобильного приложения

## 1. Объект тестирования

Мобильное приложение «Мобильный хоспис».

## 2. Цель тестирования

Проверить корректность работы основных функций приложения, навигации между экранами, обработки пользовательских данных и отображения элементов интерфейса.

## 3. Границы приложения

В рамках проекта проверяются:

- экран авторизации;
- ввод логина и пароля;
- вход с корректными данными;
- обработка неверных данных;
- главный экран приложения;
- боковое меню;
- раздел новостей;
- просмотр списка новостей;
- раскрытие и сворачивание новости;
- создание новости;
- редактирование новости;
- удаление новости;
- фильтрация новостей;
- раздел тематических цитат;
- раздел «О приложении»;
- выход из учётной записи.

Не входят в проверку:

- серверная часть приложения;
- производительность сервера;
- безопасность хранения данных;
- работа приложения на версиях Android, отличных от API 29.

## 4. Виды тестирования

Для проверки приложения используются:

- функциональное тестирование;
- UI-тестирование;
- позитивное тестирование;
- негативное тестирование;
- регрессионное тестирование;
- исследовательское тестирование.

## 5. Тестовое окружение

- операционная система: Windows;
- Android Studio;
- Android Emulator;
- устройство: Pixel 4;
- версия Android: Android 10;
- API: 29;
- Gradle: 7.2.

## 6. Тестовые данные

Корректные данные авторизации:

- логин: login2;
- пароль: password2.

Некорректные данные:

- пустой логин;
- пустой пароль;
- неверный логин;
- неверный пароль;
- пробелы вместо данных;
- специальные символы.

## 7. Инструменты

- Android Studio;
- Android Emulator;
- JUnit;
- Espresso;
- Allure;
- Git;
- GitHub.
## 8. Распределение тест-кейсов по степени автоматизации

### Планируется автоматизировать

- авторизация с корректными данными;
- авторизация с некорректными данными;
- открытие бокового меню;
- переход в раздел новостей;
- просмотр списка новостей;
- создание новости;
- редактирование новости;
- удаление новости;
- фильтрация новостей;
- переход в раздел «О приложении»;
- переход в раздел тематических цитат;
- выход из учётной записи.

### Планируется проверять вручную

- визуальное соответствие интерфейса макету;
- корректность цветов, размеров и расположения элементов;
- удобство использования приложения;
- проверка длинных текстов;
- проверка приложения при нестабильном интернет-соединении;
- исследовательское тестирование;
- проверки, которые сложно сделать стабильными UI-автотестами.
## 9. Риски

- нестабильная работа эмулятора;
- ошибки загрузки зависимостей;
- отсутствие уникальных идентификаторов у элементов интерфейса;
- зависимость тестов от текущего состояния данных;
- возможное влияние порядка запуска тестов;
- длительное выполнение UI-тестов.

## 10. Результаты работы

По итогам проверки должны быть подготовлены:

- чек-лист;
- тест-кейсы;
- UI-автотесты;
- отчёт Allure;
- файл с результатами сравнения времени ручной и автоматизированной проверки.
